# 本地会议录音软件设计

- 日期：2026-08-17
- 状态：已完成对话确认，等待书面规格复核
- 目标用户：Alan
- 目标设备：Apple Silicon Mac，当前系统 macOS 26.5.1

## 1. 目标与成功标准

做一个只在 Alan 自己的 Mac 上使用的轻量菜单栏录音软件。会议开始后，Alan 可以通过全局快捷键或菜单栏按钮立即开始录音；软件同时录制全部系统声音和当前麦克风声音，并把两路声音混合保存为一个本地 M4A 文件。

第一版成功的标准：

1. 不依赖 Zoom、Google Meet、腾讯会议或企业微信会议的接口。
2. 软件不在前台时，全局快捷键仍能可靠开始和停止录音。
3. 开始录音时不弹命名窗口，不打断会议。
4. 菜单栏始终准确显示待机、准备、录音、保存或错误状态。
5. 最终文件可以正常播放，并同时听到系统声音和 Alan 的麦克风声音。
6. 单次录音没有固定时长上限；只受可用磁盘空间和系统运行状态限制。
7. 所有录音只保存在本机，不联网、不上传、不做分析。

## 2. 已确认事实、约束与偏好

### 已确认事实

- 当前项目目录在设计开始时为空，也不是现有 Git 仓库。
- 当前设备为 Apple Silicon，系统为 macOS 26.5.1。
- Apple 的 ScreenCaptureKit 提供系统声音和麦克风采集输出。
- Apple 的 AVAssetWriter 支持分段写入；支持的媒体容器可在意外中断后保留已经写入的部分内容。

### 硬性约束

- 第一版只给 Alan 自己使用，不做公开分发。
- 使用原生 macOS 技术路线，不安装 BlackHole 等虚拟声卡。
- 同时录制全部系统声音和当前麦克风声音。
- 两路声音混合成一个最终文件，不保留独立音轨。
- 录音开始时必须立即执行，不先询问会议名称。
- 默认保存根目录为；用户可以在设置中修改：

  `/Users/alan/Documents/快速本地录音软件/录音文件/`

- 必须按录音开始日期建立 `YYYY-MM-DD` 子文件夹。
- 不设置 60 分钟或其他固定录音时长上限。

### 用户偏好

- 默认快捷键：`Control + Option + R`。
- 软件常驻菜单栏，不显示 Dock 图标，不保持普通窗口常开。
- 可选择登录 Mac 后自动启动，建议默认开启。
- 界面使用 Alan UI 风格：冷灰三层背景、细边框、小圆角、紧凑字号、极少阴影；红色只表达录音状态，低饱和棕色表达警告或权限异常。
- 停止后发送无声音系统通知，点击可在 Finder 中定位文件。

### 已知但接受的行为

- 为了兼容所有会议软件，第一版录制全部系统声音。录音期间的通知提示音、浏览器媒体或其他应用声音也可能进入录音。
- 虽然软件不保存屏幕画面，macOS 仍会要求与屏幕和系统音频录制相关的系统权限。

## 3. 技术路线选择

### 采用：原生 macOS 菜单栏应用

- Swift 作为主要开发语言。
- AppKit 负责菜单栏应用生命周期和系统级交互；SwiftUI 可用于菜单栏弹层与设置界面。
- ScreenCaptureKit 负责系统声音和麦克风声音采集。
- AVFoundation 负责格式转换、时间对齐、混音、编码和文件完成。

选择原因：这是满足“个人使用、Mac 专用、轻量、快捷键立即录音”的最直接方案。它不需要虚拟声卡，也不需要 Web 运行时或原生辅助进程之间的通信。

### 未采用的方案

1. **Tauri 加原生录音模块**：界面扩展能力更强，但第一版会增加跨进程通信、打包和故障排查成本，没有对应收益。
2. **FFmpeg 加 BlackHole**：可以较快做出原型，但会改变系统音频路由，对耳机、麦克风和会议软件切换更敏感，不符合轻量、稳定的目标。

## 4. 日常使用流程

### 首次使用

1. 启动后检查系统音频录制权限和麦克风权限。
2. 对缺少的权限说明用途，并提供“打开系统设置”。
3. 显示默认保存位置和默认快捷键。
4. 提供“登录 Mac 后自动启动”选项。
5. 明确提醒用户只在自己有权录制的会议中使用。

### 开始录音

1. Alan 按下 `Control + Option + R`，或点击菜单栏中的“开始录音”。
2. 应用进入“准备录音”，检查权限、保存目录和可用空间。
3. 检查通过后创建日期目录和内部临时文件。
4. 只有系统声音、麦克风和文件写入都已经成功启动，界面才进入“录音中”。
5. 菜单栏图标变红，并显示录音时长。

### 录音中

- 展开菜单栏弹层可看到系统声音和麦克风的独立音量指示。
- 菜单栏红色状态持续可见，不播放开始或停止提示音。
- 再次按快捷键或点击“停止并保存”进入保存过程。
- 快速连续触发只执行当前状态允许的一次操作。

### 停止录音

1. 停止采集新的声音。
2. 完成临时媒体文件并生成最终 M4A。
3. 成功后删除不再需要的临时文件。
4. 菜单栏恢复待机状态。
5. 发送无声音系统通知：“录音已保存”。

## 5. 文件与音频规则

### 目录和命名

目录结构：

```text
/Users/alan/Documents/快速本地录音软件/录音文件/
└── YYYY-MM-DD/
    └── 会议录音-YYYY-MM-DD-HH-mm-ss.m4a
```

- 日期和时间使用录音开始时的本地时间。
- 录音跨过午夜时，仍保存在开始录音当天的文件夹，不自动切断。
- 同一秒出现重名时追加 `-2`、`-3`，绝不覆盖已有文件。
- 异常恢复文件在原名称后追加 `-未完整恢复`。

### 音频参数

- 最终容器：M4A。
- 编码：AAC。
- 采样率：48 kHz。
- 声道：立体声。
- 目标码率：128 kbps。
- 系统声音和麦克风混合为一个音轨。
- 第一版不做自动增益、降噪、回声消除或响度标准化，避免引入不可控失真。
- 一小时目标文件大小约 58 MB，验收上限为 70 MB。

## 6. 软件结构

### `MenuBarUI`

显示待机、准备录音、录音中、正在保存和错误状态；提供开始、停止、打开当天文件夹和设置入口。

### `HotkeyService`

注册全局快捷键，处理快捷键冲突和按键重复。优先使用系统热键注册，不监听或保存其他按键。计划不申请辅助功能或输入监控权限。

### `PermissionService`

检查系统音频录制和麦克风权限。权限不足时返回具体原因，不允许界面进入录音状态。

### `CaptureEngine`

通过 ScreenCaptureKit 接收系统声音和麦克风样本。系统声音覆盖录音期间的全部系统输出；麦克风优先跟随当前系统默认输入设备。

### `AudioPipeline`

把两路样本转换到统一格式，按照媒体时间戳对齐并混合，持续写入内部可恢复文件。音量指示来自实时样本，不从最终文件回读。

### `RecordingStore`

负责日期目录、唯一文件名、剩余空间检查、临时文件、最终文件完成和异常恢复扫描。所有文件操作限制在用户设置的录音根目录内。

### `AppSettings`

保存录音根目录、全局快捷键和登录时启动设置。第一版不保存会议内容索引或录音数据库。

## 7. 状态模型

允许的主流程：

```text
待机 → 准备录音 → 录音中 → 正在保存 → 待机
```

规则：

- `待机` 才能开始录音。
- `准备录音` 期间再次触发快捷键不会创建第二个任务。
- `录音中` 再次触发快捷键只执行一次停止。
- 单个音源异常但仍可继续录音时，保持在 `录音中` 并叠加警告状态；只有无法继续可靠写入时才进入错误状态。
- `正在保存` 期间不接受新的开始请求。
- 任一步骤失败都进入带具体原因的错误状态。
- 错误被用户确认或条件恢复后回到待机。

## 8. 可恢复写入设计

首选方案：

1. 录音期间把混合后的 AAC 音频写入支持分段写入的内部 QuickTime 临时文件。
2. 初始恢复节点目标为 1 秒，后续恢复节点目标为 10 秒。
3. 正常停止时完成临时文件，并在不重新编码的前提下转换或重新封装为最终 M4A。
4. 下次启动扫描未完成临时文件，恢复出可播放音频，并以 `-未完整恢复` 命名。

实现必须先完成一个小范围技术验证：证明“纯音频分段临时文件、强制结束应用、重新启动、恢复、生成 M4A”在当前 macOS 上完整可行。

如果该验证不通过，确定采用备用方案：每 10 秒完成一个独立 AAC 片段；正常停止时无损合并为一个 M4A，异常启动时合并已经完成的片段。两个方案的外部行为、最终文件格式和恢复命名规则相同。

## 9. 异常处理

### 开始前

- 权限不足：不开始，说明缺少哪项权限并打开对应系统设置。
- 保存目录无法创建或写入：不开始，显示目录和错误原因。
- 可用空间低于 1 GB：不开始，提示释放空间或修改保存位置。
- 快捷键冲突：菜单栏仍可操作，设置中要求更换快捷键。

### 录音中

- 默认麦克风变化：尝试切换到新的默认输入设备。
- 麦克风断开且切换失败：继续保存系统声音，菜单栏显示明确警告。
- 系统声音捕获中断：停止录音并尽可能完成已有内容。
- 文件无法继续写入：停止采集，尝试完成已有内容并显示写入错误。
- 录音期间阻止 Mac 因空闲自动睡眠；停止或失败后立即解除阻止。

### 退出与异常终止

- 用户主动退出：如果正在录音，先停止并完成保存，再退出。
- 应用崩溃或系统异常重启：下次启动自动运行恢复扫描。
- 恢复失败：保留原始临时文件，不静默删除，并说明文件位置。

## 10. 视觉设计

使用 Alan UI 的任务型工具风格，但不强行加入应用侧边栏。菜单栏弹层属于系统覆盖层，可以使用克制的深色阴影；普通内容主要依靠三层冷灰背景和 1px 边框建立层次。

- 主色：冷灰、近黑和白色。
- 正文：13px；辅助信息：11–12px；计时：17px，使用等宽数字。
- 按钮高度：32px；控件圆角：5–6px；面板圆角：8px。
- 红色只表示正在录音或录音相关停止操作。
- 低饱和棕色只表示权限、设备或写入异常。
- 正常音源使用低饱和绿色文字和音量条。
- 所有键盘可操作控件保留清晰焦点状态。
- 已检查 1440px 桌面宽度和 500px 窄窗口，无内容溢出。

## 11. 第一版范围外

- 自动识别会议开始或结束。
- 只录指定会议软件。
- 文字转录、摘要和待办提取。
- 音频剪辑、降噪、自动增益和音量增强。
- 系统声音与麦克风分轨保存。
- 云同步、账号、使用数据分析和远程服务。
- Windows 版本。
- App Store 或公司范围分发。

## 12. 验收与验证

### 功能验证

1. 在应用不处于前台时，快捷键可以可靠开始和停止。
2. 菜单栏按钮与快捷键触发相同的状态变化。
3. Zoom、Google Meet、腾讯会议和企业微信会议分别进行真实测试，确认可以听到对方和 Alan；未安装或无法进入测试会议的平台必须标记为未验证。
4. 文件进入正确日期目录，跨午夜不拆分，重名不覆盖。
5. 系统声音和麦克风音量指示与实际输入状态一致。
6. 权限不足、空间不足和写入失败时，不显示错误的“正在录音”状态。

### 稳定性验证

1. 连续录音 60 分钟，最终文件可播放；在开始和结束位置分别测量同一测试信号，两路声音的相对时差变化不超过 100 ms，并通过人工听取确认没有可察觉的持续漂移。
2. 连续录音至少 3 小时，不能因内部计时、缓冲或文件大小限制自动停止。
3. 快速重复触发快捷键，不产生并行录音或文件覆盖。
4. 录音中更换或断开麦克风，系统声音继续保存并显示准确状态。
5. 录音中强制结束应用，重新启动后恢复已写入内容。
6. 用户主动退出时完成保存，不留下无说明的临时文件。

### 资源目标

- 待机 CPU 接近 0%。
- 录音期间平均 CPU 低于 5%。
- 录音期间内存低于 150 MB。
- 一小时文件小于 70 MB。

以上资源数值必须在 Alan 当前这台 Mac 上实测；未实测前只能称为目标，不能称为已达到。

## 13. 实施前必须验证的未知项

1. ScreenCaptureKit 在当前 macOS 上同时输出系统声音和麦克风时的实际同步表现。
2. 默认麦克风在录音中切换时，是否可以不中断系统声音并平滑更新采集配置。
3. 全局热键在当前系统上是否无需辅助功能或输入监控权限。
4. 纯音频分段 QuickTime 临时文件能否在强制结束后恢复，并无损生成 M4A。
5. Zoom、Google Meet、腾讯会议和企业微信会议在当前设备上的真实录音结果。
6. 60 分钟与 3 小时录音的资源占用、文件大小、时间漂移和恢复表现。

这些项目是实施和验收的一部分。任何一项未通过时，都必须报告真实结果，并按照本设计中已经明确的错误行为或备用写入方案处理。
